# rocket:what — question

No stages, no state file, no worktree, no edits.

1. Find the facts yourself (read code, docs, issues, run read-only commands). Do not ask the user for things you can look up.
2. Answer directly in the user's language (conventions §1). Lead with the answer, then the reasoning. Cite files as `path:line`.
3. If the answer reveals work worth doing, end with **one** clickable question offering the fitting workflow (for example *Fix it (rocket:fix)* / *No*). Never start it unasked.
